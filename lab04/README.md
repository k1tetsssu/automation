# Отчёт по лабораторной работе №4: Настройка Jenkins для автоматизации DevOps задач

## 1. Описание проекта

Цель данного проекта — изучение принципов конфигурации Jenkins для автоматизации задач DevOps и управления CI/CD конвейерами. В ходе выполнения работы была развернута инфраструктура, состоящая из Jenkins Controller и изолированного SSH-агента с поддержкой PHP и SQLite. Инфраструктура развернута с использованием Docker и Docker Compose. Также был создан и успешно выполнен декларативный Jenkins Pipeline для автоматизированной проверки окружения, инициализации базы данных и тестирования PHP-приложения.

## 2. Шаги по настройке Jenkins Controller
1. В корне проекта был создан файл `docker-compose.yml`.

2. В файле был описан сервис `jenkins-controller` на базе официального LTS-образа (`jenkins/jenkins:lts`).
3. Для сервиса были проброшены порты `8080` (для веб-интерфейса) и `50000` (для JNLP-агентов), а также подключен volume `jenkins_home` для сохранения данных и настроек при перезапуске контейнеров.
4. Контейнер был запущен командой `docker-compose up -d`.
5. После запуска была произведена первичная настройка Jenkins через веб-интерфейс: ввод первоначального пароля администратора и установка рекомендуемого базового набора плагинов.

## 3. Шаги по настройке SSH агента
1. Была создана папка `secrets`, внутри которой с помощью `ssh-keygen` была сгенерирована пара SSH-ключей без парольной фразы.

2. Был написан кастомный `Dockerfile` на базе `jenkins/ssh-agent`, в который были установлены необходимые для тестов пакеты: `php-cli` и `php-sqlite3`.
3. В `docker-compose.yml` добавлен сервис `ssh-agent`. Публичный SSH-ключ передавался в контейнер через переменную окружения `JENKINS_AGENT_SSH_PUBKEY` с помощью файла `.env`.
4. В Jenkins (раздел **Manage Credentials**) был добавлен Global Credential с типом *SSH Username with private key*, содержащий сгенерированный приватный ключ.
5. В разделе **Manage Nodes** был создан новый узел `ssh-agent1` с меткой `php-agent`. В качестве метода запуска выбрано *Launch agents via SSH*. Узел был успешно подключен.

## 4. Шаги по созданию и настройке Jenkins pipeline
1. В репозиторий проекта на GitHub был добавлен файл `Jenkinsfile`.

2. В пайплайне была указана привязка к агенту: `agent { label 'php-agent' }`.
3. Были описаны следующие стадии:
   * **Environment Check:** Проверка версии PHP и наличия драйвера PDO SQLite.

   * **Prepare Test Database:** Резервное копирование оригинальной конфигурации, генерация тестового файла `config.php` с абсолютными путями, очистка старой БД и автоматическое применение SQL-схемы к новой тестовой базе SQLite.
   * **Install Dependencies:** Проверка наличия Composer и установка зависимостей.
   * **Run Tests:** Линтинг файлов и запуск скрипта `tests.php` с проверкой на успешное выполнение всех 7 тестов.
4. Добавлен блок `post { always }` для гарантированного восстановления оригинального `config.php` и удаления тестовой базы данных `test_database.db`.
5. В Jenkins была создана задача типа **Pipeline**, настроено получение `Jenkinsfile` из GitHub, после чего конвейер был успешно запущен.

## 5. Ответы на контрольные вопросы

**1. Какие преимущества использования Jenkins для автоматизации DevOps задач?**

* **Открытый исходный код:** Проект бесплатный и поддерживается огромным сообществом.

* **Масштабируемость:** Распределенная архитектура Controller-Agent позволяет выполнять множество сборок параллельно в разных окружениях.
* **Pipeline as Code:** Конфигурация конвейера хранится в репозитории (Jenkinsfile), что позволяет версионировать пайплайны вместе с кодом.
* **Богатая экосистема:** Огромное количество плагинов для интеграции с Git, Docker, облачными провайдерами и инструментами тестирования.

**2. Какие другие типы агентов Jenkins существуют?**
* **Inbound (JNLP) агенты:** Агент сам инициирует подключение к контроллеру. Полезно, когда агент находится за NAT или в закрытой сети.

* **Динамические агенты (Docker/Kubernetes):** Jenkins может автоматически поднимать эфемерные контейнеры (pods) на время выполнения сборки и уничтожать их после завершения.
* **Локальные агенты (Built-in Node):** Запуск процессов прямо на контроллере (строго не рекомендуется для нагруженных систем).

**3. С какими проблемами вы столкнулись при настройке Jenkins и как вы их решили?**
В ходе настройки пайплайна пришлось решить несколько архитектурных проблем изоляции тестов:
* **Проблема:** Ошибка `could not find driver` при попытке подключения к базе данных.

  **Решение:** В `Dockerfile` SSH-агента был добавлен пакет `php-sqlite3` для поддержки нужного PDO драйвера.

* **Проблема:** Конфликт путей к файлу базы данных при запуске `init_db.php` и самих тестов из разных директорий.

  **Решение:** В сгенерированном `config.php` был применен абсолютный путь с использованием магической константы PHP `__DIR__`, что обеспечило правильный резолв пути к БД независимо от точки входа.
* **Проблема:** Синтаксические ошибки при генерации многострочных PHP-скриптов средствами bash (`echo '...' > file`).

  **Решение:** Был использован встроенный в Jenkins декларативный шаг `writeFile`, который безопасно записывает многострочные файлы без риска конфликта кавычек и спецсимволов.
